# 伝説のバイクガチャ & GARAGE

ガチャでバイクを集め、ガレージで管理・カスタムできるブラウザゲームです。
Python / Streamlit で作成し、AWS（EC2）上に自分で構築・公開・運用しています。AI駆動開発で作成しました。

- 公開URL: http://35.72.1.171/
- ソースコード: `bike_gacha_app.py`（1ファイル、約170行）

## 遊び方

1. 画面上部に所持コイン（初期 1,000G）と所持マシン数が表示されます。
2. 「ガチャを回す」タブで、100G を払ってガチャを回します。数秒の演出のあと、バイクが1台排出されます。SSR が出ると風船の演出が入ります。
3. 「ガレージ & カスタム」タブで、手持ちのバイクを選び、ターボキットを装着できます（馬力 +50 PS、最高速 +30 km/h）。

## 使用技術

- 言語・フレームワーク: Python, Streamlit
- インフラ: AWS（EC2, IAM）, Amazon Linux 2023, nginx, systemd

```
ブラウザ → nginx（80番） → Streamlit（systemdで常駐） ／ EC2（東京リージョン）
```

## ファイル構成

| ファイル | 内容 |
|---|---|
| `bike_gacha_app.py` | アプリ本体（画面・ガチャ・ガレージのすべて） |
| `requirements.txt` | 依存パッケージ（`streamlit` のみ。バージョン指定なし） |

## ローカルでの起動方法

```bash
pip install -r requirements.txt
streamlit run bike_gacha_app.py
```

起動後、ブラウザで表示されるURL（通常 `http://localhost:8501`）を開きます。

## コードの解説

`bike_gacha_app.py` は、上から下へ順に実行される1本のスクリプトです。Streamlit は、画面の操作（ボタンを押すなど）のたびにこのスクリプトを**最初から再実行**して画面を作り直します。この仕組みを前提に読むと分かりやすくなります。

### 1. 準備（ファイル冒頭）

- `import random, time, streamlit as st`: 抽選用の `random`、演出の待ち時間用の `time`、画面用の `streamlit`。
- `st.set_page_config(...)`: タブのタイトル、アイコン、画面幅（`wide`）の設定。
- `st.markdown("<style>...</style>", unsafe_allow_html=True)`: 背景色やネオン風タイトル、ガチャ結果のカードの見た目を、CSS で指定しています。

### 2. バイクのデータ（`BIKE_DATABASE`）

排出されるバイクを、辞書（名前、レア度、色、馬力 `hp`、最高速 `speed`、画像URL）のリストで持っています。全4種類です。

| バイク | レア度 | 馬力 | 最高速 |
|---|---|---|---|
| NR-999 サイバーファントム | SSR | 210 | 340 |
| GSX-R 1000 レジェンド | SSR | 202 | 310 |
| ナイトストライカー 400 | SR | 53 | 180 |
| ストリートクラシック 250 | R | 26 | 140 |

画像は Unsplash の外部URLを直接参照しています（リンク先が変わると表示されなくなります）。

### 3. 状態の保持（`st.session_state`）

Streamlit は画面操作のたびにスクリプトを再実行するため、変数はそのままでは消えてしまいます。そこで、消えてほしくない値を `st.session_state` に入れています。

- `my_garage`: 所持バイクのリスト（最初は空）
- `coins`: 所持コイン（最初は 1000）

`if "..." not in st.session_state:` と書くことで、最初の1回だけ初期化しています。

### 4. ヘッダーとタブ

- タイトルと、`st.columns(2)` による所持コイン・所持マシン数の表示（`st.metric`）。
- `st.tabs([...])` で「ガチャ」と「ガレージ」の2画面に分けています。

### 5. ガチャ画面（タブ1）

ボタンが押されたときの流れは次のとおりです。

1. コインが 100G 未満なら、エラーを出して終了。
2. 100G を引く。
3. 演出：進捗バー（`st.progress`）を 100 ステップ進める（1ステップ 0.015 秒、合計約1.5秒）。途中でメッセージを切り替え、終わったら消す。
4. 抽選：`random.choices(BIKE_DATABASE, weights=[5, 10, 35, 50], k=1)` で重み付き抽選。
5. 当たったバイクを `.copy()` してガレージに追加。コピーするのは、あとでカスタムしたときに元データ（`BIKE_DATABASE`）が書き換わらないようにするためです。
6. SSR なら風船と特別メッセージ、それ以外は通常メッセージ。
7. 当たったバイクをカードと画像で表示。

#### 排出確率

`weights` の数値は合計100なので、そのまま確率（%）になります。

| レア度 | 内訳 | 確率 |
|---|---|---|
| SSR | NR-999: 5%、GSX-R 1000: 10% | 15% |
| SR | ナイトストライカー 400 | 35% |
| R | ストリートクラシック 250 | 50% |

抽選は、ブラウザではなく**サーバー側の Python** で実行されます。ブラウザには結果の表示だけが送られます。

### 6. ガレージ画面（タブ2）

- 所持バイクがなければ案内文を表示。
- ある場合は、ドロップダウン（`st.selectbox`）で1台選び、画像とレア度、ステータスを表示。
- 「ターボキット装着」ボタンで、そのバイクの `hp` と `speed` を加算し、名前に ` [TURBO]` を付けます。そのあと `st.rerun()` で画面を再描画し、最新のステータスを表示します。

## 現状の仕様と制限

- データはブラウザのセッション内だけで保持しています。ページを再読み込みするとコイン（1,000G）とガレージは初期状態に戻ります。
- コインを増やす手段はありません。1セッションで回せるガチャは最大10回です。
- ターボキットは回数制限・コストなしで、押すたびに名前に ` [TURBO]` が付き足されます。
- ログイン、データベース、ランキングなどの共有機能はありません。

## 技術選定

- 当初は JavaScript・HTML/CSS で着手しましたが、Python のみで画面まで実装できる Streamlit に気づき、1言語に集約するため切り替えました。
- 結果的に、抽選などの処理をサーバー側で保持でき、ブラウザ側での改ざんを避けられる構成となりました。

## 気を付けた点

- **セキュリティ**: root ユーザーは MFA で保護し、日常作業は権限を分けた IAM ユーザーで実施。SSH は自分の IP のみ許可し、外部公開は nginx の80番のみとしました。
- **可用性**: systemd で自動起動と異常終了時の自動再起動を設定し、SSH を切ってもアプリが動き続ける状態にしました。
- **通信**: Streamlit に必須の WebSocket 通信が途切れないよう、nginx に Upgrade ヘッダの設定を追加しました。
- **コスト**: 予算アラートを設定し、想定外の課金を防止しました。

## コードの確認・改善

AI が書いたコードをそのまま使わず、読んで確認・修正しています。

- **抽選確率**: コメント（SSR 15%）と実際の重み（SSR 25%）がずれていることに気づき、コメントに合わせて重みを修正しました。
- **保守性**: 画面に出た Streamlit の非推奨警告を確認し、新しいパラメータに置き換えました。
